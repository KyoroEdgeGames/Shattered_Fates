## ?? Performance Monitoring

### Widget Complexity Budget
```
Total Widgets on Screen: < 10 active
Draw Calls per Widget:   < 20
Update Frequency:         Variable (not every frame)
```

### Optimization Checklist
- [ ] Use Invalidation Boxes for static UI
- [ ] Disable Tick on hidden widgets
- [ ] Pool frequently created widgets
- [ ] Use texture atlases for UI images
- [ ] Minimize transparent overlays

## ?? Testing Scenarios

### Scenario 1: Health System
```
1. Take damage ? Health bar decreases
2. Health < 30% ? Bar turns red
3. Health = 0 ? Life lost, health restored
4. Lives = 0 ? Game over
```

### Scenario 2: Stamina System
```
1. Sprint ? Stamina depletes
2. Stamina = 0 ? Can't sprint
3. Stop sprinting ? Stamina regenerates
4. Pounce (costs 20 stamina) ? Check availability
```

### Scenario 3: Movement States
```
1. Walk ? Display "Walking"
2. Sprint ? Display "Sprinting" (yellow)
3. Crouch ? Display "Crouching" (blue)
4. Jump/Fall ? Display "Falling" (orange)
5. Climb ? Display "Climbing" (green)
```

### Scenario 4: Menu Flow
```
Main Menu ? Play ? Game Level
Game Level ? Pause ? Resume ? Game Level
Game Level ? Pause ? Main Menu ? Main Menu Level
Game Level ? Pause ? Restart ? Game Level (reloaded)
```

### Scenario 5: Dialogue System
```
1. Trigger dialogue ? Dialogue box appears
2. Typewriter effect plays
3. Click continue ? Next line
4. Last line ? Continue ? Dialogue closes
5. Auto-advance dialogue ? Automatic progression
```

## ?? Common Mistakes to Avoid

1. ? **Wrong component names** ? Must match exactly (case-sensitive)
2. ? **Forgetting anchors** ? UI breaks on different resolutions
3. ? **No parent class set** ? Widget won't have C++ functionality
4. ? **Missing input mappings** ? Controls won't work
5. ? **Z-order conflicts** ? Widgets overlap incorrectly
6. ? **Updating every frame** ? Performance issues
7. ? **Not handling nullptr** ? Crash if widget not created
8. ? **Ignoring input modes** ? Mouse/keyboard conflicts

## ? Validation Checklist

Before testing, verify:
- [ ] All component names match C++ exactly
- [ ] Parent classes set correctly
- [ ] Anchors configured for all widgets
- [ ] Input actions assigned in blueprints
- [ ] Widget classes assigned in GameMode/HUD
- [ ] Z-order set appropriately (HUD=0, Dialogue=100, Pause=999)
- [ ] Mouse cursor logic correct (show in menus, hide in game)
- [ ] Input modes correct (Game/UI/GameAndUI)
